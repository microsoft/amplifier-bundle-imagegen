# Provenance and changes

Thanks to **[robotdad](https://github.com/robotdad)** for the original
[amplifier-module-image-generation](https://github.com/robotdad/amplifier-module-image-generation)
library and its OpenAI/Google clients. The upstream source used is
[`79836889ee0787b44206ce6a48492a5aec476282`](https://github.com/robotdad/amplifier-module-image-generation/tree/79836889ee0787b44206ce6a48492a5aec476282).
Its licensing declaration is preserved in [UPSTREAM-NOTICES.md](UPSTREAM-NOTICES.md).

This repository intentionally starts a **new Git history**. Its immediate source
is the reviewed private integration revision
`0b2b05a1718c42b1cfcff655f03254f49ceae69a` of
`bkrabach/amplifier-module-image-generation`, which retains upstream history.
That repository and its existing consumers are preserved independently.

The original client/library/model/wrapper APIs and tests remain here. The modern
integration adds a normal Amplifier mount and tool schema, explicitly selected
host or built-in backends, safe workspace artifact handling, exclusive durable
request claims, unknown-result status, edit lineage, receipt hashes, no implicit
paid fallback/retry, and lifecycle cleanup. Google Imagen generation remains
available through explicit Vertex API-key configuration; it has no live-account
qualification here.

For this fresh repository, the distribution and Python package were renamed to
`amplifier-module-tool-image` and `amplifier_module_tool_image`. Source, tests and
examples were mechanically updated for those names; the tool name remains
`image_generate`, the module entrypoint remains `tool-image`, and receipt schema
remains `amplifier.image.receipt.v1`. Direct imports move to the new package; the
`ImageGenerator` and `ImageGenerationTool` classes retain their existing behavior.
Generated bytecode, caches, virtual environments, old Git history and historical
process notes were omitted. No new image-generation behavior was introduced.

The predecessor passed offline Core 2/source-loading checks and real OpenAI
host-backend generate/edit acceptance. Those historical results establish the
implementation baseline; this renamed package receives separate offline
packaging/source-loader tests, not an assumed new live acceptance.
